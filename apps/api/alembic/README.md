# Migrations

The only supported way to change the database schema.

```bash
# after editing a model in app/models/tables/
alembic revision --autogenerate -m "add promotion audit reviewer index"
alembic upgrade head
```

Rules:

- **Never** edit a schema by hand, in any environment. If it is not in a
  migration, it does not exist.
- **Never** edit a migration that has been applied anywhere but your machine.
  Write a follow-up revision instead.
- Review autogenerated migrations before committing — autogenerate misses
  server defaults, index renames, and anything on a table module that is not
  imported in `env.py`.
- Every migration needs a working `downgrade()`. If a change genuinely cannot
  be reversed (a destructive backfill), say so in the docstring rather than
  leaving `pass` unexplained.
