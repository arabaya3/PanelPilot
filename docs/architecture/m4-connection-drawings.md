# M4: review-only connection drawings from the saved model

## 1. Scope

M4 adds one review export, `connection_drawing_pdf`: a paginated drawing of a saved `pp-design/2` revision's components, terminal strips, terminals, nets, connections and wires. It is generated from the revision's stored snapshot only, and is marked review-only and NOT FOR EXECUTION on every sheet, like the terminal and wire schedules.

M4 also adds optional **symbol data** on a component template (`symbol`), so the drawing's symbols come from data. A template without one is drawn as a labelled placeholder ("symbol not defined").

Out of scope: any engineering content (ratings, cross-sections, colours, numbering, standards), routing optimisation, a schematic of the v1 power design (the existing drawing set does that), editing, DXF or ECAD output of the connection drawing, and any execution-readiness gate (M7).

## 3. Interface for consistency tests

`connection_drawing.drawing_set(model: DesignModelV2) -> DrawingSet` is deterministic and pure. A `DrawingSet` holds:

- `terminal_rows`: exactly `schedules.terminal_schedule(model)` (the same tuple, in the same order). Every drawn terminal row is one of them.
- `wire_rows`: exactly `schedules.wire_schedule(model)`.
- `rows`: one `Row` per terminal row, in the same order: its `terminal` (the `TerminalRow` itself), `key` (`TerminalRef.key`), `label`, `place` (`Place`: sheet, column, slot, the page point `x`/`y` where the terminal's point is drawn, and `zone` such as `2B`, read from that point), `notes` (unconnected, unrealised) and `ends`. Each `End` is one connection at that terminal: `connection_id`, `via`, `net_id`, `signal`, `far_key`, `far_label`, `far_board`, `qualified` (far end on another board), `far_place`, the `WireRow` when there is a wire, `wire_missing`, and the cable `core`.
- `sheets`: drawing sheets (`Sheet`: `number`, `board_id` (its first board), `boards`, `parts`); each `BlockPart` is the part of one component's or strip's block (or one board's list of components with no terminals and no symbol, `owner_kind == "no_terminals"`, with its `members`) on that sheet, with its `lines` (each a row's note, end or bridge, with its `slot` and `span`), `symbol`, `continued_from` / `continues_on`, and its geometry: `texts` (each `Text` with its baseline point, size, tone, role, row key and index), `points`, `stubs`, `buses`, `bridges`, `dotted`, `leads`, the symbol `frame` or `placeholder`, and its edges.
- `full_texts`: every value cut on a drawing sheet, in full; `[n]` on a sheet refers to the n-th. `owners`: each component's and strip's printed name (`<board>/<designation>`) and header place. `locate(location)` names where a finding's location is drawn.
- `places`: the sheet and zone of every terminal, by `TerminalRef.key`.
- `open_items`: `OpenItem(kind, board_id, subject, text, place)`, kinds in `OPEN_KINDS`: an unrealised net (subject the net id), an unconnected terminal (required, requiredness unresolved, documented not required, strip point; subject the row label), a wire record missing (connection id), an unset or assumed wire attribute (wire id), a designation not set, a symbol not defined, a template with no terminals (component or strip id).
- `connections`, `nets`: every connection and net id of the model.
- Text helpers used for every printed value: `cell_text`, `wire_text`, `end_texts`, `row_marking`, `row_net`; `NOT_SET` is `"not set"`.
- Helpers `terminal_keys()`, `net_ids()`, `wire_ids()`, `connection_ids()` for set comparison with the schedules and the model.

Invariants a consistency test can hold the layout to:

1. `[row.terminal for row in rows] == terminal_rows`, `terminal_keys()` is the schedule's terminals, `wire_ids() == {wire.id for wire in model.wires}`, `net_ids() == {net.id for net in model.nets}`, `connection_ids() == {connection.id for connection in model.connections}`.
2. Every connection is drawn at both ends; each end names the other end's label, sheet and zone, and a wire end carries its `WireRow` (number, cross-section and colour cells with sources).
3. Every terminal in no net is drawn with an `UNCONNECTED`/`unconnected` note and listed as an open item; every member of a net its connections do not join carries an `UNREALISED` note and the net is listed.
4. Every sheet's text holds the export's label, `CONNECTION DRAWING — REVIEW ONLY — NOT FOR EXECUTION`, `Snapshot SHA-256: <hash>` and `Sheet n of N`.

`model/test_connection_drawing.py` and `test_connection_drawing_pdf.py` (DB-free, every configuration) and `test_the_connection_drawing_and_schedules_of_a_revision_agree` (DB, through the export route) hold these today. The hash printed is `DrawingHeader.design_sha256`, the revision row's `snapshot_sha256`.

The export path is one function call: `design_projects._schedule_export(project, row, read, format, mark, applicable)` for all three formats, with `read` from one `_check_snapshot` call.

## 4. What the drawing shows, and how

- **Sheets.** A3 landscape. Sheet 1 is the cover: project, revision, full snapshot hash, schema, rules and renderer version, legend, sheet index. Drawing sheets follow, in board order. By default (D-9, open: `BOARDS_SHARE_SHEETS`) a board continues on the sheet and column of the board before it after a blank slot, so small boards do not take a sheet each; every block's title names its board (`K1 (component), board DB-1`), and the title block and sheet index list every board on a sheet. `drawing_set(model, boards_share_sheets=False)` starts each board on a new sheet. Then the open-items sheets, the full-text sheets (when a value was cut), the sheet index and the findings sheets (structural findings with their effects and where each is drawn, then the design's other findings). Every text sheet holds whole entries inside the inner frame with a 4 mm margin: an entry that does not fit moves whole to the next sheet (only an entry taller than a sheet continues, and says so). Every sheet: frame, zone grid (columns `1..8`, rows `A..F`), title block (project, revision, sheet `n of N`, board, hash, schema, renderer version), the export's mark top and foot (as the schedules) and `CONNECTION DRAWING — REVIEW ONLY — NOT FOR EXECUTION` in the same red (`#b00020`, bold) as the schedules' label.
- **Blocks.** Components first, then strips, in the terminal schedule's order, three block columns to a sheet. A block is its header, the symbol (or the placeholder) and one or more slots per line of its rows (a slot holds two text lines; a wrapped text takes more). A marking, a block title (name and kind) and each word of a cross-reference are never broken across lines: a block whose longest such value does not fit one column takes two or three columns. A block too tall for the space left is continued in the next column or sheet, saying "continued from / continues on" with the other part's sheet and zone; a block starts in a partly used column when it would be split anyway.
- **Components with no terminals.** Components whose templates define no terminals and no symbol (every legacy v1 device) are not drawn as a placeholder each: one compact list per board names each (designation and template), two to a slot; a block taking several columns is followed in the same column by the next block, and one open item per board lists every member with its id, template and where it is listed (M5-0, refines D-8). Nothing is hidden.
- **Symbols and leads.** From the template's `symbol` (Section 4a), scaled into the block. Anchors sit on the symbol's edge. A lead leaves its anchor perpendicular to its edge, passes round the symbol (above it from the top edge, below it from the bottom edge, round the top or bottom from the left edge, each further out than the leads it passes), runs in its own lane of the gutter right of the symbol and enters its point from the left. Leads cannot cross when the rows are in the clockwise order of their anchors (`exit_order`); the layout keeps the schedule's row order when it has that property and otherwise orders the block's anchored rows by pin, saying so in the header ("rows in the symbol's pin order, so no leads cross"). Lanes are shared only by leads whose runs do not overlap, so no two leads meet and none enters the symbol's box. Where no crossing-free routing exists (two anchors at one point, or no room for the lanes) no lead is drawn: the header says so, the pin markings are printed at the symbol and a `leads_not_drawn` open item is listed. A terminal with no anchor, and every row of a placeholder, gets a short dotted stub, never guessed onto a pin. A strip's symbol is drawn without anchors (D-7). A template with no symbol, or a strip with no template, is drawn as a dashed box labelled `symbol not defined` and listed as an open item.
- **Text size.** A product readability target, **not** an electrical drawing standard: body text and labels (markings, cross-references, notes, block headers, every text-sheet line) are never smaller than **6 pt**; secondary detail printed in grey (the wire-detail and net lines, a symbol's own text and pin markings repeated at a symbol) never smaller than **5 pt**; titles 7.5 pt. At A3, 6 pt Helvetica has a cap height of about 1.5 mm and stays legible on a full-size print and on screen at page width, while three block columns still fit a sheet; 5 pt is kept only for grey text that repeats or details something printed at 6 pt nearby. Nothing is shrunk below these sizes: a long text wraps onto more lines, a block takes more slots or columns, a list continues on more sheets.
- **Long values.** Nothing is cut silently. A value wraps in full at spaces, and a word wider than its room breaks after a hyphen, slash, underscore, dot, colon, comma or bracket. Only a piece with no such break that is wider than its whole room is cut, with `…[n]`, and printed in full as `[n]` on the full-text sheets. A finding's message that quotes a value shortened by the findings code (`…`) is marked `…[Fn]`, with a note under it saying where the value is in full.
- **Notes.** Every row says something: its ends, or why it has none (`UNCONNECTED`, `UNREALISED`, or `in net <signal> alone: no connection`). A component whose template defines no terminals (every legacy v1 device) is drawn as a header and placeholder and listed.
- **Connections.** Each connection is drawn as a stub at each of its ends, labelled with the far end's label (a strip point with its side and level; with its board, `B2/K1:A1`, when the far end is on another board), where its point is drawn (`sheet 4, zone 6B`, or `this sheet, zone 2A`) and its `via`. Zones are read from the page point where the far end's point is drawn, from the same coordinates the renderer draws, so a zone cannot disagree with the drawing. Lines are not routed across the sheet: cross-references are always written, so nothing depends on following a line.
- **Strip bridges.** Where a strip point's two sides are joined by a connection the model records (`via: internal` or `jumper`), and neither side has another connection or note, the two sides are drawn together: a bar right of the two points joining their stubs (the bridge mark), one cross-reference per side, and one grey line `bridge between the point's sides: <via> per template` (declared by a pattern) or `per model`. Nothing else is asserted about it.
- **Wires.** A wire's stub names its id (the wire schedule's key) and its number, cross-section and colour with their source; a value the model does not hold prints `not set`, an assumed one prints the value with `assumed (<assumption id>)`. Nothing is filled in. A connection with no wire record prints `no wire record (via <via>)`; its internal id is not printed on the sheet (a missing record's id is in the open items).
- **Findings.** Each structural finding names where it is drawn when its location is on the drawing (`— drawn at DB-1/K1:A1 (sheet 2, zone 1B)`: board, designation and marking, sheet and zone), with its internal ids after it as secondary text.
- **Open items, shown where they are and listed.** On the row: `UNCONNECTED: required (documented)`, `UNCONNECTED: requiredness unresolved`, `unconnected: not required (documented)`, `UNCONNECTED: this point side is in no net`; `UNREALISED: net <signal> (<id>) is not joined by its connections` for every member of such a net; a `via: wire` connection with no wire record as `WIRE RECORD MISSING`; a missing designation as `designation not set`. All of them are listed again on the open-items sheets.
- **Never invented.** Markings, designations, signals, wire attributes, requiredness and review status are printed only as the snapshot holds them; otherwise `not set` or `unresolved`. No standard is named, and the cover says that nothing on the drawing states or checks a rating, size, colour, numbering convention or standard.

## 4a. Symbol data

A template may carry `symbol: {width, height, shapes, anchors}`: whole numbers in a grid of at most 100 by 100, y downwards; `shapes` (at most 64) are `line` (x1 y1 x2 y2), `rect` (x y width height), `circle` (cx cy r) and `text` (x y, with its `text`), sorted by kind, points and text; `anchors` name a terminal of the template and a point on the grid's edge, sorted by terminal. Every shape's whole extent (a circle's centre plus and minus its radius) lies within `0..width` by `0..height`; text is at most 8 characters; nesting deeper than 64 levels anywhere in a v2 payload is refused as unreadable. Anything else is refused when the snapshot is read (`codec_v2._symbol`), including an anchor naming no terminal of the template. The key is written only when present, so every template without one keeps its canonical JSON, `registry_lock` digest and review subject digest; a symbol is part of both digests, so a review decision covers it. Configurations count shapes and anchors in the template size limit.

## 5. Gating

`connection_drawing_pdf` is added to `SCHEDULE_FORMATS`, so it follows exactly the schedules' path: refused for a draft and for a `pp-design/1` revision (`schedule_requires_v2`), and for a revision through the same integrity, stale, approval-binding and plan path; `purpose: execution` is refused (`execution_package_incomplete`) before anything else; the restricted formats (`UNPROTECTED_FORMATS`) are unchanged and stay refused. It is protected (not in `UNPROTECTED_FORMATS`): the mark is printed on every sheet.

`DESIGN_SNAPSHOT_SCHEMA` still defaults to `pp-design/1`; the drawing exists only for revisions saved as `pp-design/2`.

## 6. Renderer version

The v2 renderer version is bumped (now `2026.11.01.v2-6`, for the M5-0 layout; it was `2026.11.01.v2-5`), the two M4 configurations with symbol data are fingerprint cases too, and the drawing of each fingerprint case is recorded in `renderer_fingerprints_v2.json`, held by `test_renderer_version.py` like the schedules: content changed without a version bump fails.

## 7. Test data

Every synthetic configuration in `app/tests/design/model/configurations/` is drawn (seven). Two are added by M4, both with symbol data:

- `drawing_control_relay`: symbols, a template without one, an undocumented template, an unrealised net, user and assumed wire values, a component without a designation.
- `drawing_heldout_feeder`: added after the renderer, as data only. Its commit ("Add a held-out connection drawing case as data only") adds the JSON configuration and its new entry in `findings_fingerprints.json` (an addition; no existing entry changes) and nothing else. It has its own templates and symbols, and a 30-point strip that continues across columns and sheets, with a wire crossing sheets. `test_the_held_out_configuration_is_data_only` checks that the layout and renderer name no configuration, template, pattern, designation or device word.
