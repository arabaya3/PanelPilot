## Defects / observations

- **D1 (low, UI only, safe direction).** After "Request execution export" on a v2 revision, the "Execution export refused" notice lists only the package gaps (`params.missing`) and drops the v2 execution blockers. The API's `params.blockers` carries `template_unreviewed` and `pattern_unreviewed` (see 4-exec-refusal-v2-api.log), but `executionRefusalOf` (apps/web/src/components/design/readiness.ts) reads only not_validated and stale from `blockers`. The export is still refused correctly. Repro: switch ON, save a configured revision, go to Review & export, click Request execution export, and compare the list with the 409 body. A related point: `execution_blockers` on the project uses bare codes (`template_unreviewed`), not the `finding:<code>` form `executionBlockersOf` expects. The pre-refusal notice would therefore show them as raw LTR codes in the "missing" list. I did not capture that screenshot.
- **O1 (pre-existing, outside scope).** In Arabic at 390 px the trial and account notice button row overflows the viewport by about 3 to 5 px, so the page scrolls horizontally (account-session area, not touched by commit a08b3cf).
- **O2.** Structural finding messages and the PDFs are English-only in the ar and he UI (server text). Legacy (server-designed) components are labelled "Data (from definitions)", which can read oddly for devices the server designed.
